### 0.98 `mergeReSlice` — real, already fixed in #171, now pinned

The prescribed crash is exact. The old guard was `if (!p || !result) return;`, so a truthy primitive from the worker reached the `in` probes and threw `TypeError: Cannot use 'in' operator to search for 'agmReference' in text`. #171 changed the guard to `!result || typeof result !== "object"`, and nothing tested it.

The test **executes** the shipped function: it is sliced out of `ui.js` and run in a `vm` context whose only real state is the payload, with every module helper stubbed. Four hostile primitives — a string, a number, a boolean and a symbol — must be ignored without mutating the payload; a real `{cells, customCut}` slice must still merge; the guard must precede both `in` probes. Reverting the line to its pre-#171 form fails the suite with the exact `TypeError` above. `mergeReSlice` is a `validate-guard` on `multiple-sites`, and that is now what the code does and what the tests require.

### 0.96 `populatePrintSheet` — the sink is real, the path is closed

The sheet is assembled with `innerHTML`, so the prescription is not wrong that a sink exists. It is wrong that anything untrusted reaches it, and the test answers that field by field rather than dismissing it:

- the only string field the sheet interpolates is `basis`, and `readInputs` assigns it exclusively from literals (`"monthly electric bill"`, `"direct kWh entry"`, …) — never a form value, never the hash;
- every hash-originated string field is whitelisted in `restoreFromShare` **before** it can set a control: `ch` via `CHEM_KEYS`, `uc` via `useCase()`, `at`/`ag`/`hw`/`fc` via explicit arrays, `sel` via a dense pattern. The test enumerates all seven, so deleting one fails the suite;
- the share codec is permissive **by design** — `parseShareHash` bounds only `la`/`lo`/`kw` and spreads the rest. The test proves it by round-tripping `ch: "<img src=x onerror=alert(1)>"` through the real codec and getting the string back verbatim. That is what makes those whitelists load-bearing rather than decorative, and it is the assumption a future refactor is most likely to break.

Every other value in the sheet is a number, a formatter output, a module literal, or an engine-supplied label. Disposition: **no change**, with the defence pinned.

### 0.95 `clearCompactCache` — obsolete, not unfixed

There is no definition of it anywhere in `assets/`; `git log -S` shows it removed in `43f5378b`. Its job — dropping a compact series whose year window is stale — now happens inline at the single call site in `nasa.js`, and `idbDelete` guards for a missing object store and swallows its own errors, so the call is safe fire-and-forget. Nothing to harden and nothing to test.
