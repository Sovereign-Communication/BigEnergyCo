### What the new tests actually pin

Each runs shipped code sliced out of `ui.js` in a `vm`, with only module state and collaborators stubbed, so the assertions are about arithmetic and state:

- every display-currency figure — tariff, export rate, fixed charge — is converted to USD exactly once, and left alone when there is no currency;
- bill mode derives kWh/day from the bill and never from a leftover number in the kWh box, and the derivation becomes the new slider anchor;
- an unusable load entry yields `NaN`, which is what makes `run()` refuse it instead of sizing a system nobody asked for;
- off-grid prefers its own slider and falls back to the numeric box;
- a roof area caps the PV envelope in kW, and an unusable area caps nothing;
- `setLevel` moves the ladder without rendering when there is no payload;
- `syncCutControls` clamps to 1–150, rounds, and writes slider, label and preset select from one value.

### Failing-first proof

Mutated in place, suite re-run, failure inspected: dropping `t / fx.rate` fails the FX test; `renderResults(lastPayload)` unconditionally fails the ladder test; removing the clamp fails the range test; returning `area` instead of kW fails the roof test; `el` writing `innerHTML` fails both `shared-dom` tests. The first `setLevel` mutation silently hit a coincidentally identical line in a different function, which is why each mutation's failure was read rather than assumed.
